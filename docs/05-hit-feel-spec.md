## 1. 文档说明

### 1.1 这份文档要解决什么

岗位 JD 里有一句话：**"协同程序、美术相关团队进行战斗表现的制作，优化战斗手感提升战斗表现力。"**

这句话的难点在于：**"手感"是一个没有单位的词**。策划说"这里不够重"，程序不知道要改什么数字，美术不知道要改哪一帧，音频不知道要加几毫秒。

所以这份文档的唯一使命是：**把"重 / 轻 / 脆 / 闷 / 爽"这些形容词，全部翻译成带单位的、可以被实现的、可以被验收的参数。**

读完这份文档，任何一个岗位的人应当能回答：

| 角色 | 读完能回答的问题 |
|---|---|
| **程序** | 顿帧在哪一帧开始、冻结谁、持续几帧、和别的系统怎么交互、多人叠加怎么封顶 |
| **美术（特效）** | 特效在判定帧第几帧生成、生命周期几帧、粒子数上限多少、透明度曲线是什么形状 |
| **美术（动画）** | 受击方的动画在哪一帧定住、定多久、位移几帧走完、表情从哪一帧开始 |
| **音频** | 四层声音各自在第几帧触发、长度多少、随机化幅度多大、团战时谁让位给谁 |
| **TA** | 性能预算上限在哪、降级顺序是什么、哪些效果绝对不能砍 |
| **QA** | 怎么判定"不合格"、盲测怎么做、准确率要过多少 |

### 1.2 读者与使用方式

本文档分三块使用：

```
[定义块] §2  →  策划与所有人对齐"什么叫做得好"
[实现块] §3~§11 → 程序/美术/音频/TA 按表实现，逐条对照
[验收块] §12~§14 → QA 与主策按表验收，协作按流程走
```

**最重要的使用原则：不要整篇读。** 拿到一个具体任务（比如"做重击命中"），直接查 §3.3 的帧层对齐表 + §4 顿帧表 + §5 震动表 + §7 音效表，四个表拼起来就是一个完整的需求。

### 1.3 参数变更流程

本文档是**规范**，不是讨论稿。任何数值变更都必须走以下流程，不允许"口头改一下先试试"。

| 步骤 | 动作 | 责任人 | 产出 |
|---|---|---|---|
| ① 提出 | 填写变更申请，写明**当前值 / 目标值 / 变更理由 / 影响范围** | 提出人 | 变更单 |
| ② 冲突检查 | 检查是否与 `01_白皮书` §3.2 帧数据、§3.3 有利帧推导冲突 | 战斗策划 | 冲突结论 |
| ③ 合法性校验 | 单项数值变更幅度 ≤ **8%**（白皮书 §5.3 平衡旋钮纪律）；帧数据变更必须为整数帧 | 战斗策划 | 校验结果 |
| ④ 联调验证 | 在原型 `index.html` 中改参数试玩，出对比录像 | 提出人 + 程序 | 录像 + 帧步进截图 |
| ⑤ 签核 | 主策签核后写入本文档，**版本号 +0.1** | 主策 | 新版本本文档 |

**四条硬约束（不允许绕过）：**

1. **帧数据不得在表现层被修改。** 表现层只能"延后或提前反馈"，不能改判定帧、僵直帧、有利帧。若表现层需要改帧数据，说明战斗设计有问题，回去改白皮书。
2. **顿帧必须对称施加。** 见 §4.4 的证明：非对称顿帧会直接破坏白皮书 §3.3 推导出的有利帧，属于**A 级事故**。
3. **派生值必须标注**。本文档中白皮书已定义的数值标注【白皮书 §7】，由我推导补充的标注【派生】。派生值同样有约束力，但可被主策直接调整而不触发流程 ②。
4. **单项表现参数变更 ≤ 8%**（振幅、时长、粒子数等）。超过 8% 玩家会感知为"手感被改了"，必须走完整流程 + 灰度对比。

## 2. 打击感的定义与可测化

### 2.1 五维度拆解

"手感好"这句话不成立，因为它不可测。我把它拆成五个可以在编辑器里打勾的维度。

| 维度 | 定义 | 单位 | 目标值 | 失效表现 |
|---|---|---|---|---|
| **延迟** | 从判定生效到玩家收到首次反馈的时间 | 帧 / ms | **≤ 1 帧（16.7 ms）** | "明明打中了但没感觉" |
| **反馈强度** | 单次事件的信号能量，五通道加权归一化 | 0.00 ~ 1.00 | 轻击 0.35 / 重击 0.72 / 处决 1.00 | "砍上去像砍空气" |
| **反馈密度** | 单位时间内交付的独立反馈事件数 | 事件 / 100 ms | 命中瞬间 ≥ **3**（视/听/触） | "只有一下，后面空了" |
| **反馈确定性** | 同类事件每次反馈的一致程度 | 随机化幅度上限 | 音高 ±3% / 角度 ±15° | "这一刀特别亮，那一刀特别闷" |
| **反馈层级** | 不同强度事件在感知上的可区分度 | 盲测正确率 | **≥ 85%** | "轻击和重击我分不出来" |

### 2.2 反馈预算（Feedback Budget）

**这是本文档最核心的概念。**

> **一次命中，就是一次"信息交付"。玩家的注意力在命中瞬间只有极短的窗口。如果在这个窗口内没交付够信息，玩家就会认为"手感差"，即使每一帧都有反馈。**

我把这个窗口切成四段，规定每一段**必须交付**什么、**允许交付**什么、**必须停止**什么。

| 时间窗 | 帧窗 | 名称 | 必须交付（缺失即判不合格） | 允许交付 | 禁止 |
|---|---|---|---|---|---|
| **0 ~ 17 ms** | 第 0 ~ 1 帧 | **首发窗** | ① 视觉撞击特效<br>② 音频金属层<br>③ 手柄触觉 | 低频冲击音起始 | 任何延迟 ≥ 1 帧的通道 |
| **17 ~ 50 ms** | 第 1 ~ 3 帧 | **强化窗** | ④ 顿帧生效<br>⑤ 屏幕震动起始<br>⑥ 音频低频层峰值 | 摄像机 FOV 微变起始 | 摄像机位移（会晕） |
| **50 ~ 150 ms** | 第 3 ~ 9 帧 | **情境窗** | ⑦ 伤害数字弹出<br>⑧ 韧性条变化<br>⑨ 杀势条移动 | 音频混响层尾音 | 新增高频闪烁 |
| **150 ~ 300 ms** | 第 9 ~ 18 帧 | **结算窗** | ⑩ 受击位移走完<br>⑪ 姿态恢复正常 | UI 归位动画 | 继续震动 |

**总预算：单次命中 300 ms 内交付 11 项信息。**

**超预算判定标准（QA 可直接执行）：**

| 违规 | 判定 | 处理 |
|---|---|---|
| 首发窗内三通道任一缺失 | **A 级不合格** | 阻塞提测，当日修复 |
| 强化窗内顿帧或震动未生效 | **A 级不合格** | 阻塞提测 |
| 情境窗内伤害数字延迟 > 6 帧（100 ms） | B 级不合格 | 下个迭代修复 |
| 结算窗后仍有震动 / 位移 | B 级不合格 | 下个迭代修复 |
| 反馈在 300 ms 内**超过** 11 项（过载） | C 级 | 评估删减，过载同样损害手感 |

> **过载也是一种病。** 团战时每帧都有人挨打，如果每次命中都足额交付 11 项信息，玩家会瞬间信息瘫瘓。所以 §12 的**降级策略**不是性能妥协，是**感知预算的主动管理**。

### 2.3 强度分级表（全文档的强度锚点）

所有表现参数（振幅、粒子数、音量、触觉强度）都从这张表派生，保证"重的东西处处都重"。

| 事件 | 强度值 | 顿帧 | 震幅 | 粒子数 | 触觉 |
|---|---|---|---|---|---|
| 轻击命中 | **0.35** | 3f | 6px | 12 | 40ms |
| 上挑命中 | **0.45** | 4f | 8px | 16 | 50ms |
| 格挡成功 | **0.40** | 2f / 4f | 8px | 10 | 25ms |
| 重击命中 | **0.72** | 6f | 16px | 40 | 90ms |
| 架崩 | **0.68** | 8f | 14px | 32 | 70ms |
| 破防 | **0.85** | 10f | 18px | 60 | 100ms |
| 绝技命中 | **0.90** | 8f | 24px | 150 | 140ms |
| **弹反成功** | **0.96** | **12f** | 12px | 30 | **120ms** |
| 处决 | **1.00** | 10f | 24px | 120 | 150ms |

> **注意弹反的强度分配很反直觉：它的顿帧最长（12f，全游戏最高）、强度第二（0.96），但震动振幅只有 12px、粒子只有 30。**
>
> 这是刻意的。弹反的设计语言不是"打得重"，是**"时间被夺走了"**——所以给最长的顿帧和一段慢镜，但**不给暴力画面**。用短促的金属脆响 + 长顿帧制造"时间停滞"感，比糊一屏粒子高级得多。这也是白皮书 §4.2 把弹反定义为 +22 杀势（翻盘利器）在表现层的一致兑现。

## 3. 帧层对齐规范（本文档最重要的一节）

### 3.1 零延迟原则

> **所有反馈必须在判定帧当帧触发，不允许"下一帧再播"。**

这条来自白皮书 §7，这里给出它的**工程化定义**：

```
判定帧定义：判定框（Hitbox）与受击框（Hurtbox）首次相交的那一帧 = 判定帧第 1 帧
下文统一记作 H 帧，其余事件用「H + n」表示帧偏移（n 可为负数，表示判定前）

硬性断言（必须由自动化测试守护，见 §13.2）：
  assert( VFX_impact.spawnFrame  == H )
  assert( Audio_layer2.triggerFrame == H )
  assert( Haptics.triggerFrame == H )
  assert( Hitstop.beginFrame == H )
  assert( CameraShake.beginFrame == H + 1 )   // 允许 1 帧，见下
```

**为什么摄像机震动允许晚 1 帧？** 因为震动是**位移型**反馈，若与特效同帧启动，玩家会同时收到"亮点"和"画面位移"两个强信号，产生视觉打架。延后 1 帧（16.7 ms，人眼不可分辨为"延迟"，只感知为"先亮后晃"），反馈反而**更清晰**。这是唯一被允许的 1 帧偏移，且只对摄像机生效。

**1 帧 = 16.67 ms。超过 3 帧（50 ms）玩家就会隐约感觉"打到了但没反应"。** 所以任何超过 1 帧的表现层偏移都必须走变更流程。

### 3.2 帧偏移符号约定

| 符号 | 含义 |
|---|---|
| `H` | 判定帧第 1 帧（命中帧） |
| `H − n` | 判定前 n 帧（用于预告性反馈：风声、预摄） |
| `H + n` | 判定后 n 帧 |
| `S` | 起手帧第 1 帧（Startup 开始，即输入帧） |
| `R` | 攻击方恢复帧（Recovery 结束，可行动帧） |

**为什么空挥没有顿帧？** 因为顿帧的本质是"撞击阻力"。空挥没有撞击，给顿帧会让玩家误以为打中了——**这会直接摧毁白皮书 §8.3 中"空挥杀势 −4"的惩罚反馈**。玩家必须能通过"没有停顿"瞬间判断这刀空了。

### 4.2 三种实现方案与选型

| 方案 | 实现 | 优点 | 缺点 | 采用 |
|---|---|---|---|---|
| **A. 双方冻结** | 攻守双方的状态机时间轴同时暂停 N 帧，**但 VFX / 音频 / 摄像机 / UI 继续按真实时间推进** | 视觉物理最自然（两把兵器撞在一起）；有利帧不变 | 需要状态机与表现层解耦 | ✅ **全事件采用** |
| **B. 单方冻结** | 只有受击方冻结，攻击方继续播放 | 攻击方"势如破竹"感强 | **破坏有利帧**：攻击方白得 N 帧 | ❌ 禁用 |
| **C. 全局时间缩放** | `Time.timeScale = 0` 或 `0.01` 持续 N 帧 | 实现最简单 | 会冻结所有角色（3v3 中队友也被冻）+ 物理抖动 | ❌ 禁用 |

**方案 A 的实现要求（程序必读）：**

```
状态机时钟（Gameplay Clock）     ── 冻结 ──  受顿帧影响
表现层时钟（Presentation Clock） ── 不冻结 ─ 完全不受影响

必须挂在 Presentation Clock 上的系统：
  · 粒子系统 / 拖尾 / 残影
  · 音频播放与混音
  · 屏幕震动
  · 摄像机（FOV / 位移 / 慢镜）
  · UI 动效（伤害数字、韧性条、杀势条）
  · 输入缓冲计时器（！关键，见下）

必须挂在 Gameplay Clock 上的系统：
  · 角色动画状态机与帧计数器
  · 判定框生命周期
  · 僵直计时器
  · 韧性 / 血量 / 杀势
```

> **输入缓冲计时器必须在表现层时钟上。** 白皮书 §3.6 定义输入缓冲 **8f（133ms）**。若缓冲计时器也被顿帧冻结，那么一次 12f 的弹反顿帧会额外给玩家 12 帧的缓冲宽容——**这等于偷偷把缓冲窗口从 8f 改成了 20f**，直接摧毁"抢帧仍需真实技术"的设计。这是极其隐蔽但极其致命的实现错误，必须写进代码注释。

### 4.3 3v3 顿帧叠加规则（团战防卡顿）

3v3 中同一帧可能有 4~6 个角色同时挨打。**顿帧若累加，画面会直接卡死。** 规则如下：

```
规则 1｜同帧取最大值，不累加
  顿帧 = max(所有并发事件的顿帧值)

规则 2｜8 帧内连续命中的衰减
  同一目标在 8 帧（133ms）内被再次命中：
    第 1 次：×1.00
    第 2 次：×0.60
    第 3 次：×0.36
    第 4 次及以后：×0.20（地板，不再衰减）

规则 3｜单次顿帧绝对值封顶
  顿帧 ≤ 12f（= 弹反值，即全游戏顿帧天花板）

规则 4｜顿帧预算（关键防线）
  任意 1 秒（60 帧）窗口内，累计顿帧时间 ≤ 20f（333ms）
  超出后：新增命中不产生顿帧，只保留特效 / 音效 / 震动

规则 5｜高优先级事件豁免
  处决 与 弹反成功 不受规则 4 约束，永远足额触发（它们是"必须被看见"的时刻）
```

**预算数值的推导：**

| 单秒累计顿帧 | 冻结占比 | 玩家感受 |
|---|---|---|
| ≤ 12f | ≤ 20% | 完全无感，节奏流畅 |
| **≤ 20f** | **≤ 33%** | ✅ **本作上限：能感到"打得很激烈"，但不认为游戏卡** |
| 30f | 50% | ⚠️ 开始像掉帧 |
| 45f+ | 75% | ❌ 判定为卡顿 |

**3v3 团战实测场景覆盖（必须在原型中跑通）：**

| 场景 | 并发事件数 | 原始顿帧和 | 应用规则后 | 结果 |
|---|---|---|---|---|
| 1v1 交锋 | 1 | 6f | 6f | ✅ |
| 2v1 集火同一目标 | 2 | 3+3=6f | **3f**（取 max） | ✅ |
| 3v3 全体交火 | 5 | 6+6+3+3+12=30f | **12f**（取 max） | ✅ |
| 3v3 连环爆发（处决 + 弹反同帧） | 2 | 10+12=22f | **12f** + 处决豁免 | ✅ |
| 极限压力（6 人同帧、每秒 3 轮） | 18 | 每秒 54f | **20f**（预算封顶） | ✅ |

### 4.4 顿帧与有利帧的一致性证明

**结论：对称顿帧不改变有利帧。**

```
设：
  攻击方恢复帧 A_rec = R
  防守方恢复帧 D_rec = H + Stun
  有利帧 FA = D_rec − A_rec

施加对称顿帧 N 帧后：
  A_rec' = R + N
  D_rec' = (H + Stun) + N
  FA' = (H + Stun + N) − (R + N) = D_rec − A_rec = FA  ∎

代入白皮书 §3.3 全部推导：
  轻击·壹  命中：20 − 18 = +2    → 加 3f 顿帧后：23 − 21 = +2   ✓
  轻击·贰  命中：21 − 22 = −1    → 加 3f 顿帧后：24 − 25 = −1   ✓
  轻击·叁  命中：32 − 34 = −2    → 加 5f 顿帧后：37 − 39 = −2   ✓
  重击     命中：40 − 47 = −7    → 加 6f 顿帧后：46 − 53 = −7   ✓
  轻击·壹  被格挡：18 − 18 = ±0  → 加 2f 顿帧后：20 − 20 = ±0   ✓
  重击     被格挡（架崩）：42 − 47 = −5 → 加 8f 顿帧后：50 − 55 = −5  ✓
```

**这就是为什么方案 B（单方冻结）被禁用**：若只冻结防守方 N 帧，`FA' = FA + N`，轻击·壹 会从 +2 变成 +5，整个 §3.3 的帧数据体系当场崩塌。

**自动化守护（必须实现）：**

## 5. 屏幕震动规范

### 5.1 参数表

白皮书 §7 约束：**振幅 6 ~ 24 px，单次 ≤ 0.2 s（12 帧），方向 = 攻击方向。**

| 事件 | 振幅 (px) | 频率 (Hz) | 时长 (帧) | 衰减曲线 | 方向模式 | 起始帧 |
|---|---|---|---|---|---|---|
| 轻击命中 | **6** | 28 | 4 | 四次方衰减 `(1−t)⁴` | **定向**（攻击方向） | `H+1` |
| 上挑命中 | 8 | 24 | 5 | 四次方 | **定向 + 上偏 30°** | `H+1` |
| 格挡成功 | 8 | 22 | 4 | 四次方 | 定向（沿格挡面切向） | `H+1` |
| 重击命中 | **16** | 14 | 8 | 四次方 | **定向 + 径向 20%** | `H+1` |
| 架崩 | 14 | 12 | 8 | 指数 `e^(−4t)` | 径向 | `H+1` |
| 破防 | 18 | 16 | 10 | 指数 | 径向（全向） | `H+1` |
| 绝技命中 | **24** | 10 | 12 | 指数 | 径向（全向） | `H+1` |
| 弹反成功 | **12** | 22 | 6 | 四次方（**快速截断**） | 定向（反弹方向） | `H+1` |
| 处决 | **24** | 10 | 12 | 指数 `e^(−3t)` | 径向（全向） | `H+1` |
| 受击（作为受击方） | 命中震幅 × 0.7 | 同上 | 同上 | 同上 | 定向（**反方向**） | `H+1` |

**为什么轻击用"四次方衰减"、重击用"指数衰减"？**

| 衰减 | 公式 | 感知 | 适用 |
|---|---|---|---|
| **四次方** | `A(t) = A₀ × (1 − t)^4` | 极快衰减 → **"脆"、"干脆"** | 轻击、弹反、格挡 |
| **指数** | `A(t) = A₀ × e^(−kt)` | 长尾 → **"余震"、"量级大"** | 重击、破防、处决、绝技 |

轻击必须是脆的（4 帧内结束），重击必须有余震（8~12 帧拖尾）。**这是"轻重区分"在震动通道上的第二重保障**（第一重是振幅 6 vs 16）。

### 5.2 方向性定义

```
方向 = 攻击方向向量（攻击者位置 → 受击者位置）归一化
     ± 随机抖动 15°（防重复，见 §2.1 反馈确定性上限）

定向震动（Directional）：
  震动方向恒定 = 攻击方向，摄像机沿该轴位移
  用于：轻击、上挑、格挡、重击、弹反
  效果：玩家能感知"这一刀是从哪边来的" → 提高战斗信息可读性

径向震动（Radial）：
  震动方向 = 从命中点向外的辐射，退化为"全向抖动"
  用于：破防、绝技、处决、架崩
  效果：无方向信息，纯粹的量级传递
```

**设计理由：** 定向震动是**信息**（告诉你敌人从哪来），径向震动是**情绪**（告诉你这事很大条）。轻击需要信息（玩家还在博弈中），处决只需要情绪（已经结束了）。

**必须做方向变换：** 震动方向必须在**摄像机空间**下计算，而非世界空间。摄像机旋转后若仍用世界空间方向，会出现"刀从左来、画面往右晃"的错位。

### 5.3 多源叠加规则

3v3 团战中同帧可能有多个震动源。

```
振幅叠加公式：
  A_total = A_1st + 0.5 × A_2nd + 0.25 × A_3rd + 0.125 × A_4th + ...
  即：按振幅降序排列，第 n 大源权重 = 1 / 2^(n−1)

封顶：
  A_total ≤ 24 px（白皮书 §7 振幅上限）

方向合成：
  D_total = normalize( Σ (A_i × D_i) )      // 振幅加权向量和

时长：
  T_total = max(T_i)                          // 取最长，不累加

优先级踢出：
  若并发源 > 4，只保留振幅最高的 4 个，其余丢弃
```

**优先级表（同振幅时按此排序，高优先级不被踢出）：**

| 优先级 | 事件 | 理由 |
|---|---|---|
| P0 | 处决 | 全游戏最高光时刻，绝不能被踢 |
| P0 | 玩家自身受击 | 自身反馈优先于他人 |
| P1 | 弹反成功 | 玩家的技巧兑现，必须被感知 |
| P2 | 绝技命中 | 量级最大 |
| P3 | 破防 | 状态剧变 |
| P4 | 重击 / 架崩 | — |
| P5 | 格挡 / 上挑 | — |
| P6 | 轻击 | 最容易被踢，损失最小 |

**团战实测示例：**

| 并发源 | 计算 | 结果 |
|---|---|---|
| 重击 16 + 轻击 6 | 16 + 6×0.5 = 19 | 19px |
| 处决 24 + 弹反 12 + 轻击 6 | 24 + 12×0.5 + 6×0.25 = 31.5 → **封顶** | **24px** |
| 5 个轻击同时 | 6+3+1.5+0.75 = 11.25，第 5 个被踢 | 11.25px |
| 自身受击 11.2 + 队友重击 16 | 按 P0 排序：11.2 + 16×0.5 = 19.2 | 19.2px |

### 5.4 玩家可访问性开关

**必须有，且必须默认开启上限。** 屏幕震动是前庭敏感玩家（晕动症）的主要诱因。

| 档位 | 振幅倍率 | 说明 |
|---|---|---|
| 关闭 | ×0.00 | 保留全部其他反馈 |
| 弱 | ×0.50 | 默认推荐给敏感玩家 |
| 标准 | ×1.00 | **默认值** |
| 强 | ×1.20 | 上限，不得超过 24px 的 1.2 倍（28.8px） |

**关键约束：关闭震动不得影响任何其他通道。** 关闭震动后，反馈预算 §2.2 的"首发窗"仍由视觉 + 音频 + （有手柄时）触觉满足。**不允许"关了震动就把顿帧也调小"**——顿帧是游戏机制（影响有利帧感知节奏），不是可访问性可选项。

## 6. 摄像机规范

### 6.1 基准参数（本文档新增定义）

| 参数 | 数值 | 说明 |
|---|---|---|
| 战斗基准 FOV | **60°**（水平） | 3v3 团战视角基准 |
| 基准摄像机距离 | **480 px** | 摄像机到角色中心 |
| 基准摄像机高度 | 约 1.6 倍角色身高 | 略微俯视 |
| 推近下限距离 | **320 px** | 处决用，不允许更近（会穿模） |
| 拉远上限距离 | **640 px** | 团战视野用 |
| FOV 变化上限 | **−4° / +2°** | −4° 为白皮书 §7 重击定值 |
| 摄像机位移最大速率 | 480 px/s | 超过会引发晕动 |

### 6.2 FOV 变化表

| 事件 | FOV 变化 | 上升帧 | 保持帧 | 回落帧 | 说明 |
|---|---|---|---|---|---|
| 轻击命中 | 0° | — | — | — | 不变化（保持高频手感干净） |
| 上挑命中 | −2° | 2 | 4 | 6 | |
| 格挡成功 | +1° | 2 | 2 | 4 | **正值 = 拉开**，表达"被顶开" |
| **重击命中** | **−4°** | 6（起手期内） | 6（判定后） | 10 | **白皮书 §7 定值** |
| 架崩 | −2° | 2 | 8 | 8 | 不叠加重击的 −4° |
| 破防 | −3° | 2 | 12 | 10 | |
| 绝技命中 | −8° | 8（起手期内） | 10 | 16 | 派生，独立于 −4° 上限（绝技为专属事件） |
| 弹反成功 | −3° | 2 | 6 | 6 | 快速起落，配合慢镜 |
| 处决 | −6° | 4 | 20 | 12 | 全程接管 |

**FOV 上升时机很重要：** 重击与绝技的 FOV 变化在**起手期内**就开始（H−6 与 H−8），不是为了"命中反馈"，而是**攻击预告**——白皮书 §2.2 强调"前摇帧 = 免费的预告片"，FOV 收缩就是给这个预告片配的"镜头语言"。玩家在潜意识层面感知到"镜头压过来了 → 有大事"。

### 6.3 慢镜规范

白皮书 §7 明确：**处决触发 0.35 s 慢镜。**

| 事件 | 时间缩放 | 真实时长 | 帧数（真实） | 触发帧 | 释放条件 |
|---|---|---|---|---|---|
| **处决** | **×0.25** | **0.35 s** | 21 真实帧 | `H−5`（判定前 5 帧起） | 到点自动释放 |
| 弹反成功 | ×0.35 | 0.15 s | 9 真实帧 | `H+1` | 到点自动释放 |
| 绝技命中 | ×0.30 | 0.20 s | 12 真实帧 | `H−2` | 到点自动释放 |
| 最后一击（回合结束） | ×0.20 | 0.50 s | 30 真实帧 | `H+1` | 到点自动释放 |
| 困兽之斗触发瞬间 | ×0.50 | 0.12 s | 7 真实帧 | 事件帧 | 到点自动释放 |

**慢镜的三条硬规则：**

1. **帧数据不随慢镜改变。** 慢镜是**表现层时间缩放**，逻辑帧仍然以 60 FPS 推进。视觉上处决看起来变慢了 4 倍，但 24f 的处决判定仍然是 24 帧——**否则会破坏 §4.4 的有利帧一致性**。
2. **慢镜期间不接受新的慢镜请求。** 后进先出会导致时间缩放震荡。用一个 `slowmoOwner` 变量独占。
3. **慢镜期间输入缓冲窗口必须在表现层时钟上换算。** 若慢镜 ×0.25，8f 的缓冲窗口在真实时间上变成 32f——**这会让玩家在慢镜中变得极其宽容**。实现上必须：`buffer_window_real_ms = 133 / timeScale`，即在慢镜中缩短真实窗口，保证**游戏时间 133 ms** 不变。

### 6.4 3v3 团战的取景冲突处理

**这是 3v3 相对 1v1 最大的新增技术难点。** 三组人同时交战，摄像机不可能同时服务所有战斗。

**目标冲突：** 玩家 A 正在被处决（需要推近特写），同时他的视线需要看向 300px 外的队友 B（需要拉远）。

**解决方案：摄像机事件优先级 + 单占用锁。**

```
规则 1｜同一时刻只允许 1 个「主摄像机事件」占用视角
  主事件 = 允许改变 FOV + 距离 + 角度 + 触发慢镜

规则 2｜次级事件只能改 FOV，不能改距离与角度
  次级事件上限：FOV 变化 × 0.5，且不得与主事件方向冲突

规则 3｜主事件候选与优先级
  P0：玩家自身的处决 / 被处决
  P1：玩家自身的弹反成功
  P2：玩家队友的处决 / 被处决
  P3：玩家自身的绝技命中
  P4：玩家自身的破防
  P5：其他一切

规则 4｜团战模式自动降级（关键）
  触发条件（满足任一）：
    · 同屏 ≥ 6 个角色
    · 300 px 半径内 ≥ 3 个角色处于交战状态
  降级动作：
    · 关闭所有距离推拉（距离锁定 480 px）
    · FOV 变化量 × 0.5
    · 关闭处决的摄像机接管（保留慢镜与震动）
    · 关闭景深变化

规则 5｜摄像机切换必须用「遮蔽切」（cut with cover）
  任何硬切（hard cut）必须伴随 1~2 帧的白闪 / 冲击波 / 粒子遮蔽
  不允许裸露硬切 —— 会引发晕动与空间感丧失
```

**"处决时摄像机接管"的边界：** 接管仅在**玩家参与处决**（作为处决方或被处决方）时生效。队友处决敌人时，摄像机仅在 FOV 上响应 −2°，不接管。**玩家永远保有对摄像机的最终控制权。**

## 7. 音效分层规范

### 7.1 四层结构

白皮书 §7：**音效 4 层 —— 风声 / 金属 / 低频 / 混响。**

| 层 | 名称 | 触发时机 | 时长范围 | 功能 | 可否被 ducking |
|---|---|---|---|---|---|
| **L1** | **挥砍风声（Whoosh）** | 起手期（`H−3` ~ `H−12`） | 180 ~ 260 ms | **预告**：告诉玩家"有人出招了"及其量级 | ✅ 高强度 duck |
| **L2** | **金属碰撞（Impact）** | **判定帧第 1 帧（`H`）** | 80 ~ 200 ms | **确认**：告诉玩家"打中了"及打中了什么 | ❌ **永不 duck，最高优先级** |
| **L3** | **低频冲击（Sub / Thump）** | `H` ~ `H+1` | 150 ~ 400 ms | **量级**：告诉玩家"这一下有多重" | ⚠️ 仅侧链压缩，不静音 |
| **L4** | **环境混响（Tail / Reverb）** | `H+6` ~ `H+10` | 200 ~ 1000 ms | **空间**：告诉玩家"这是在哪打" | ✅ 团战时第一个让位 |

**设计原则：L2 是不可协商的。** 其余三层都可以为它让路。因为**L2 承担白皮书 §7 的验收标准——"我能闭眼听出打没打中"**。任何导致 L2 被淹没的混音决策都是错误的。

**L2 的分支内容（必须做 4 个独立采样）：**

| 分支 | 触发条件 | 音色特征 | 高频（>4 kHz） |
|---|---|---|---|
| 命中·血肉 | 命中无护甲部位 | 钝 + 湿 | 保留 |
| 命中·金属 | 命中带甲部位 | 亮 + 尖 | 完整保留 |
| 格挡·被架 | 攻击被格挡（未架崩） | **低通 4 kHz**，"铛"变"咚" | **必须删除** |
| 架崩·崩裂 | 重击打破格挡 | 金属崩裂 + 破碎 | 保留 + 加噪 |

### 7.2 时长与包络表

| 事件 | L1 时长 | L2 时长 | L3 时长 | L4 时长 | L2 起音（Attack） |
|---|---|---|---|---|---|
| 轻击命中 | 180 ms | **80 ms** | 150 ms | 200 ms | **0 ms（瞬时）** |
| 上挑命中 | 200 ms | 100 ms | 180 ms | 250 ms | 0 ms |
| 格挡成功 | 180 ms | 120 ms | 200 ms | **400 ms** | 0 ms |
| 重击命中 | 260 ms | **160 ms** | 300 ms | **600 ms** | 0 ms |
| 架崩 | 260 ms | 200 ms | 320 ms | 500 ms | 0 ms |
| 破防 | — | 180 ms | 350 ms | **800 ms** | 0 ms |
| 绝技命中 | 300 ms | 220 ms | 400 ms | 700 ms | 0 ms |
| 弹反成功 | 120 ms | **180 ms** | 100 ms | **300 ms（长延迟）** | 0 ms |
| 处决 | 260 ms | 240 ms | 400 ms | **1000 ms** | 0 ms |

**L2 攻击段（Attack）必须为 0 ms。** 任何起音淡入（fade-in）都会引入数十毫秒的感知延迟。**L2 必须是硬起音（hard attack）**——波形第 0 个采样点即达峰值。这是 §3.1 零延迟原则在音频层的落实。

**弹反的 L4 特殊处理：** 300 ms 短尾 + **额外的 400 ms 延迟回声**（±0.4 s，反馈 2 次，逐次衰减 40%）。这不是"混响"，是**"余音绕梁"**——用听觉的"时间感"呼应弹反在机制上的"夺走时间"。

### 7.3 随机化防重复

单次命中的一模一样 = 玩家在第 20 次听到时会完全无感。必须有随机化，但**必须封顶**（§2.1 反馈确定性：音高 ±3%）。

| 层 | 变体数 | 音高随机 | 音量随机 | 时间随机 | 防连续重复 |
|---|---|---|---|---|---|
| L1 | **5** | ±3% | ±1.5 dB | ±10 ms | **最近 2 次用过的变体不选** |
| L2 | **5 / 分支** | **±2%** | ±1.0 dB | **0 ms** | 最近 1 次用过的变体不选 |
| L3 | **3** | ±3% | ±2.0 dB | ±5 ms | 最近 1 次不选 |
| L4 | **2 / 场景** | ±1% | ±1.5 dB | ±20 ms | 无（长尾自然去重） |

**为什么 L2 的音高随机只有 ±2%（最窄）？** 因为 L2 是**信息通道**。如果音高随机幅度太大，玩家会把"随机的音色变化"误读为"打中了不同的东西"——**信息通道的随机化必须最小化**。

**防连续重复的伪代码：**

```javascript
class LayeredSfxPool {
  constructor(variants, cooldown = 2) {
    this.variants = variants;      // 音频变体数组
    this.cooldown = cooldown;      // 冷却次数
    this.recent = [];              // 最近播放记录（FIFO）
  }
  pick() {
    const available = this.variants.filter(v => !this.recent.includes(v.id));
    const pool = available.length ? available : this.variants;   // 兜底
    const chosen = pool[Math.floor(Math.random() * pool.length)];
    this.recent.push(chosen.id);
    if (this.recent.length > this.cooldown) this.recent.shift();
    return chosen;
  }
}
```

### 7.4 混音优先级与 Ducking

**整体优先级（高 → 低）：**

```
P0  弹反成功 L2          ← 玩家的技巧兑现，绝对不可被淹没
P0  处决 L2
P1  自身受击 L2
P1  自身格挡 L2
P2  队友受击 L3/L2
P2  敌方受击 L2（距离 ≤ 400px）
P3  自身 L1 风声
P3  敌方 L1 风声（距离 ≤ 600px）
P4  队友 L1/L2（远距离）
P5  UI 音效（伤害数字、杀势阈值）
P6  L4 环境混响
P7  环境音（背景音乐、场景氛围）
```

**Ducking 规则表：**

| 场景 | 被压制的层 | 压制量 | 恢复时间 | 说明 |
|---|---|---|---|---|
| 常态 | — | 0 dB | — | |
| 单次命中（1v1） | P7 环境音 | **−6 dB** | 250 ms | 轻微让路，不突兀 |
| 重击命中 | P7 + P6 | **−9 dB** | 400 ms | |
| **弹反成功** | **P7 + P6 + 全部 L4** | **−15 dB** | **600 ms** | 全场景静音一瞬，突出脆响 |
| **处决** | **P7 + 全部 L1 / L3 / L4** | **−18 dB** | 1200 ms | 只听得到处决音 |
| **团战模式**（同屏 ≥ 6 角色） | **P6 全部 L4 混响** | **−6 dB 常驻** | — | **团战时混响层全程让位**（见下） |
| 团战模式 | P4 队友音效 | −4 dB | — | |
| 团战模式 | P2 敌方 L2（>250px） | −3 dB | — | |
| 困兽之斗触发 | P7 | −10 dB + 心跳音追加 | 800 ms | |

**团战混音的核心决策：L4 混响层全程让位 −6 dB。**

理由：混响是**长尾**（600~1000 ms）。6 个角色每秒互相命中 5~8 次，如果每次的 1000 ms 混响都完整播放，**同屏会有 5~8 层混响尾巴叠加**，结果是一团糊。混响层是唯一"叠加会变糊"的层（L2 是瞬时的，叠加只是变响，不会变糊）——所以**它必须第一个让位**。

**总输出约束：**

| 指标 | 上限 | 说明 |
|---|---|---|
| 峰值电平 | **≤ −1 dBFS** | 防止削波 |
| 短时响度（1 s） | ≤ −14 LUFS | 保证长时间游玩不疲劳 |
| 同位同时播放的 L2 实例 | ≤ **4** | 超过则合并为 1 个"群组音" |
| 同位同时播放的 L4 实例 | ≤ **2** | 超过则丢弃最新的 |

## 8. 特效规范

### 8.1 生成帧（零延迟的硬约束）

白皮书 §7 明确：**命中特效必须在判定帧第 1 帧生成（零延迟）。**

```
生成帧规则：
  VFX.spawnFrame == H           // H = 判定帧第 1 帧
  VFX.worldPosition = HitPoint  // 判定框与受击框的相交点（不是角色根节点！）
  VFX.forwardDir = normalize(Target.pos − Attacker.pos)

为什么必须用「相交点」而非角色根节点？
  用角色根节点 → 特效出现在脚下，玩家感知为"特效在角色身上闪了一下"，丢失方位信息
  用相交点     → 特效出现在刀刃接触处，玩家能感知"这一刀砍在哪"
```

**判定帧未命中时的处理：** 判定框存在但未与任何受击框相交 → **不生成任何命中特效**，只保留 L1 风声。这是"空挥杀势 −4"（白皮书 §8.3）在表现层的对应：**空挥必须是"安静且空的"。**

### 8.2 生命周期与透明度曲线

| 事件 | 总生命周期 | 帧数 | 透明度曲线 | 粒子数 | 拖尾 | 残影 |
|---|---|---|---|---|---|---|
| 轻击命中 | 200 ms | 12f | 0→100%(0-20%) → easeout quartic→0(20-100%) | **12** | ✅ 短 | ❌ |
| 上挑命中 | 250 ms | 15f | 同上 | 16 | ✅ 短 | ❌ |
| 格挡成功 | 150 ms | 9f | 快速衰减（0-10% 起，easeout cubic） | **10** | ❌ | ❌ |
| 重击命中 | 350 ms | 21f | 0→100%(0-25%) → easeout quartic→0 | **40** | ✅ 长 | ✅ 4 残影 |
| 架崩 | 300 ms | 18f | 同上 | 32 | ✅ 中 | ❌ |
| 破防 | 400 ms | 24f | 0→100%(0-15%) → 两段衰减 | **60** | ✅ 中 | ❌ |
| 绝技命中 | 500 ms | 30f | 0→100%(0-30%) → easeout quint→0 | **150** | ✅ 极长 | ✅ 6 残影 |
| 弹反成功 | 300 ms | 18f | **0→100%(0-8%) → 极快衰减** | **30** | ❌ | ❌ |
| 处决 | 600 ms | 36f | 0→100%(0-20%) → 长尾线性衰减 | **120** | ✅ 长 | ✅ 3 残影 |

**透明度曲线的统一形状（必须遵守）：**

```
Alpha(t), t ∈ [0, 1]

        1.0 ┤      ▄▄▄▄▄▄▄
            │    ▄▀         ▀▄▄
            │  ▄▀               ▀▀▄▄
            │▄▀                       ▀▀▄▄▄▄▄▄
        0.0 ┼──────────────────────────────────
            0   0.2                     1.0
            │←保持→│←────── 衰减 ──────→│
```

- **保持段（0 ~ 20%）：** 100% 不透明。这一段是"被看见"的关键。
- **衰减段（20% ~ 100%）：** `Alpha = (1 − t')^4`，其中 `t' = (t − 0.2) / 0.8`。
- **四次方衰减**而非线性：因为线性淡出在中段会显得"糊"，而四次方在 50% 处仍有 6.25% 的不透明度，视觉上"啪"一下就没了——**符合撞击的物理直觉**。

**弹反是唯一例外：** 保持段只有 8%（极短），衰减极快。因为弹反的视觉主体是**白色冲击环**（一个几何体，用径向扩张而非透明度消退），而不是粒子。粒子只是配角。

**残影必须用"角色姿态快照"而非"全模型复制"：** 用单层半透明 Skinned Mesh，共享同一骨骼层级，仅烘焙姿态矩阵，禁用材质属性块（MaterialPropertyBlock）以支持合批。

## 9. 受击反馈（Hurt Feedback）规范

### 9.1 动画停顿

**受击方的第一反应必须是"停"，而不是"被打退"。**

| 事件 | 冻结时长 | 冻结内容 | 恢复后的僵直 | 总不可行动时间 |
|---|---|---|---|---|
| 轻击命中 | 3f（顿帧） | 当前动画帧完全冻结 | **14f（轻僵直）** | 3 + 14 = 17f |
| 重击命中 | 6f | 同上 | **22f（重僵直）** | 6 + 22 = 28f |
| 上挑命中 | 4f | 同上 | **18f** | 4 + 18 = 22f |
| 破防 | 10f | 同上 | **40f（破防硬直）** | 10 + 40 = 50f |
| 处决 | 10f | 同上 | 24f→IDLE | 10 + 24 = 34f |
| 弹反反弹 | 12f | 同上 | **22f（反弹硬直）** | 12 + 22 = 34f |

**"冻结"的准确含义：** 动画**时间轴**停止推进（`Animator.speed = 0`），但**物理**继续（粒子、布料、布娃娃的次级动力学不停）。这产生一种非常微妙的质感——**"人定住了，但身上的东西还在动"**，这正是"撞进肉里"的视觉表达。

### 9.2 位移规范

白皮书 §3.2 击退距离：轻击壹 25px / 轻击贰 35px / 轻击叁 110px / 重击 150px / 上挑 60px / 绝技 200px。

| 击退量 | 前段（70% 距离） | 后段（30% 距离） | 总帧数 | 曲线 |
|---|---|---|---|---|
| **25px**（轻击壹） | 3f，速度 ≈ 5.8 px/f | 2f，匀减速 | **5f** | ease-out quad |
| **35px**（轻击贰） | 3f，速度 ≈ 8.2 px/f | 3f | **6f** | ease-out quad |
| **60px**（上挑） | 4f，速度 ≈ 10.5 px/f | 4f | **8f** | ease-out quad |
| **110px**（轻击叁） | 4f，速度 ≈ 19.3 px/f | 5f | **9f** | ease-out cubic |
| **150px**（重击） | 4f，速度 ≈ 26.3 px/f | 4f | **8f** | ease-out cubic |
| **200px**（绝技） | 5f，速度 ≈ 28.0 px/f | 6f | **11f** | ease-out cubic |

**前段 70% / 后段 30% 的分配原理：**

```
位置(t) 曲线：
  1.0 ┤        ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄
      │      ▄▀
  0.7 ┤   ▄▀   ← 70% 距离在 50% 时间内完成
      │ ▄▀
      │▀
  0.0 ┼────────────────────────────
      0                  T

"撞"的阶段要快（速度感），"滑"的阶段要慢（重量感）。
若全程匀速 → 像被风扇吹走，没有质量
若全程 ease-out → 像被磁铁吸走，没有冲击
```

**位移必须与 §6 的摄像机震动方向解耦：** 位移是**受击方**沿攻击方向的位移；震动是**摄像机**的位移。两者方向相同但在不同坐标系，实现时必须分开，否则会出现"角色也抖、镜头也抖"的双重抖动，玩家会晕。

**撞墙处理（白皮书 §8.2）：** 击退路径上若有墙体/障碍，位移在接触帧立即归零，且**追加一次撞墙反馈**：屏幕震动 +6px（径向）、L2 追加"闷响"音效、受击方额外 4f 硬直（派生，不改变有利帧推导中的"贴墙 0px 回位"结论，因为硬直属于受击方，会**增加**攻击方优势——这正是白皮书 §8.2 "贴墙危险"的表现层兑现）。

### 9.3 材质受击

受击瞬间，受击方角色的**材质层**必须有反应。这是低成本高收益的表现手段。

| 参数 | 变化量 | 持续 | 曲线 | 说明 |
|---|---|---|---|---|
| BaseColor 亮度 | **+15%** | 2f | 线性归零 | "闪白"，最关键的材质反馈 |
| Metallic | **−0.30** | 6f | 线性回归 | 材料"变钝"，暗示受创 |
| Roughness | **+0.20** | 6f | 线性回归 | 表面变粗糙 |
| 描边（Rim Light） | 强度 **×2.5** | 3f | 指数归零 | 突出剪影，远处也能看清 |
| 顶点扭曲 | 幅度 **2 px** | 3f | 指数归零 | 低成本"受创"感 |

**复杂度分级（按事件强度）：**

| 强度档 | 事件 | 启用的材质参数 |
|---|---|---|
| 低（< 0.5） | 轻击、上挑、格挡 | 仅 BaseColor + Rim |
| 中（0.5~0.8） | 重击、架崩 | BaseColor + Rim + Roughness |
| 高（≥ 0.8） | 破防、绝技、处决、弹反 | **全部 5 项** |

**必须用 MaterialPropertyBlock（或等效的 per-instance 参数）实现**，不允许为了闪白而拷贝材质实例——3v3 中 6 个角色 × 多次受击会瞬间产生数百个材质实例，导致合批失效、DrawCall 爆炸。

### 9.4 表情与血液/碎屑方向

**表情（面部 BlendShape）：**

| 事件 | 表情 | 强度 | 起始帧 | 持续 |
|---|---|---|---|---|
| 轻击命中 | 皱眉 + 咬牙 | 0.4 | `H` | 6f |
| 上挑命中 | 皱眉 + 抬头 | 0.45 | `H` | 7f |
| 重击命中 | 咬牙 + 闭眼 + 头部后仰 | 0.8 | `H` | 10f |
| 破防 | 张嘴 + 闭眼（失衡） | 1.0 | `H` | 20f |
| 弹反（被弹反方） | 惊讶（睁眼 + 张嘴） | 0.9 | `H` | 12f |
| 处决（受方） | 痛苦 | 1.0 | `H` | 24f |

**表情必须在 `H` 帧触发（零延迟）。** BlendShape 的权重过渡时间为 2f（33 ms）——**不允许用更长的过渡**，否则表情会"慢慢浮现"，与撞击的瞬时性冲突。

**血液 / 碎屑方向：**

```
方向 = normalize(Target.pos − Attacker.pos) 的半球方向
     锥角：以攻击方向为轴，半角 45°
     额外抖动：±15°（随机）
     初速度：与 §2.3 强度值正相关

速度公式：v = 200 + 600 × intensity   (px/s)
  轻击 (0.35)：v = 410 px/s
  重击 (0.72)：v = 632 px/s
  处决 (1.00)：v = 800 px/s

重力：980 px/s²（与战斗场景重力一致）
生命周期：0.3 ~ 0.8 s（与 §8.2 特效生命周期同步）
```

| 事件 | 血液粒子数 | 碎屑粒子数 | 是否留地面痕迹 |
|---|---|---|---|
| 轻击命中 | 6 | 0 | ❌ |
| 重击命中 | 18 | 6（甲片） | ✅（小，≤ 8s） |
| 破防 | 24 | 12（装甲碎片） | ✅（中，≤ 15s） |
| 处决 | 40 | 24（甲片 + 武器碎片） | ✅（大，≤ 30s） |

**地面痕迹必须做数量上限（≤ 12 个，FIFO 淘汰）**，否则 3v3 长局后场景会累积大量的贴花导致性能下降。这是很容易被忽略的"慢性性能问题"。

**分级开关（必做）：** 血液强度必须支持三档（关闭 / 弱化 / 完整），且**默认跟随分区分级**（不同地区发行要求不同）。关闭血液时，改为"碎屑"或"能量粒子"，**不得让反馈强度下降**（§13 盲测中不能因为关闭血液而失败）。

## 10. UI 与信息反馈

### 10.1 伤害数字分级

伤害数字是**唯一的定量反馈通道**——玩家从它读取"我这一刀值多少"。

| 事件 | 显示值 | 字号 | 颜色 | 描边 | 位移距离 | 停留时间 | 峰值缩放 |
|---|---|---|---|---|---|---|---|

| 轻击叁命中 | 104（115×0.90≈103.5，见注） | 30 pt | 亮白 | 1.5 px 黑 | 30 px | 0.8 s | 1.0 → 1.20 |
| 上挑命中 | 95 | 26 pt | 白 | 1 px 黑 | 26 px | 0.7 s | 1.0 → 1.15 |

> **注：** 白皮书 §5.1 定义连段递减 `×(1 − 0.05(n−1))`。**伤害数字显示的是递减后的最终值**，但**在数字右下角追加一行 8 pt 灰字显示倍率**（如 `×0.95`），仅在高段位对局或训练模式开启。理由：递减是"防止一套连死"的机制（白皮书 §5.1），玩家应当能理解它；但在正常对局中显示会制造信息噪音。

**数字弹出动效曲线（所有伤害数字统一）：**

```
缩放 (Scale)：
  第 0 帧：1.00
  第 1 帧：峰值（按上表）   ← 1 帧内冲顶，制造"爆出"感
  第 2 ~ 8 帧：峰值 → 1.00（ease-out back）
  之后：保持 1.00

位移 (Offset)：
  第 0 帧：0
  全程：线性上浮至峰值距离
  最后 20% 时间：额外 8 px 上浮 + Alpha → 0

透明度：
  0 ~ 80%：100%
  80 ~ 100%：线性 → 0
```

**必须做的三件事：**

1. **数字必须做"堆叠避让"**——同一目标连续受击时，新数字不能完全覆盖旧数字，必须按 12 px 垂直间隔堆叠。
2. **数字必须可被玩家隐藏**（设置项），但**隐藏后必须保持"命中确认"的替代通道**（如准星或屏幕边缘的脉冲）。
3. **同时存在的伤害数字 ≤ 16 个**，超出按 FIFO 强制淡出。

### 10.2 韧性条动效

白皮书 §3.4：最大韧性 100，自然回复 12/s。

| 状态 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| 减少（受削韧） | 条体缩短，前置白色"残影条"先到新位置 | **3f** | ease-out quad |
| 白色残影条追平 | 残影条从新位置缩回真实值 | 6f | 线性 |
| 受击（削韧 > 20） | 条体闪橙 1 次 | 4f | 脉冲 |
| 自然回复 | 条体以 **12/s** 速率增长，颜色偏蓝 | 实时 | 线性 |
| **归零（破防）** | ① 条体碎裂（碎片飞散）<br>② 条体置灰<br>③ 4f 内闪烁 2 次 | 4f | 阶跃 |
| 破防结束 | 恢复为实心，从 0 开始回复 | — | — |

**残影条（Ghost Bar）是最重要的设计。** 玩家不需要盯着一根条的数值，只需要看"残影条离满还有多远"就能判断刚刚这一下削了多少韧。这是典型的"用动效替代数值阅读"的设计。

**必须注意：韧性条的视觉位置应尽量靠近角色（或作为角色血条的子条），而不是固定在屏幕角落。** 3v3 中玩家需要同时读出 6 个角色的韧性状态，将韧性条绑定在角色头顶的悬浮 UI（World-space UI）是最优解；屏幕中央只显示**当前锁定目标**的详细韧性条。

### 10.3 杀势条动效

白皮书 §4.2/§4.3：杀势 −100 ~ +100，双方共享；阈值 30 / 60 / 90；自然衰减 3/s。

| 事件 | M 变化 | 条体动效 | 额外反馈 |
|---|---|---|---|
| 轻击命中 | **+6** | 6f 平滑移动 | — |
| 上挑命中 | **+7** | 7f 平滑移动 | — |
| 重击命中 | **+10** | 8f 平滑移动 + 单次脉冲 | 条体闪金 2f |
| 绝技命中 | **+14** | 10f 平滑移动 + 双脉冲 | 条体闪橙 4f |
| 攻击被格挡 | **+3** | 4f 平滑移动（幅度小） | — |
| **弹反成功** | **+22** | **12f 专属高亮脉冲动效** | 条体全宽闪白 + 位移冲击波 |
| 攻击被闪避 | **−4** | 6f 反向移动 | 条体短暂降饱和 3f |
| 被弹反 | **−8** | 8f 反向移动 + 抖动 | 条体红色闪烁 4f |
| 处决成功 | **+25** | 14f 满幅脉冲 | 条体全宽金色扫光 |
| 自然衰减 | −3/s | 实时线性向 0 收拢 | 无（必须低调，不能每次都闪） |
| **跨越 30 / 60 / 90 阈值** | — | **条体跨越侧生成"台阶光带"，持续 8f** | 屏幕中央提示（0.8s） |
| 进入"碾压"（≥90） | — | 条体持续微弱脉动（1 Hz） | — |
| **触发困兽之斗（≤ −60）** | — | **屏幕边缘红色脉冲 6f** | **心跳音 + 环境音 duck −10 dB** |

**阈值跨越必须有"台阶感"。** 白皮书 §4.3 明确"离散阈值在玩家心理上产生台阶感"，表现层必须兑现：阈值跨越时用**独立的光带 + 提示音**（不同于常规移动音效），让玩家听得出"我升级了"。

**困兽之斗的视觉提示必须极其明确。** 这是白皮书 §4.4 反滚雪球机制的核心，如果玩家不知道自己进入了困兽状态（弹反窗口 8f → 12f），这个机制就白设计了。**屏幕边缘红脉冲是必须的**，不能只靠一个小图标。

### 10.4 击杀与处决的 UI 反馈

| 事件 | UI 反馈 | 时长 | 说明 |
|---|---|---|---|
| **被处决（自身）** | ① 屏幕红边（Alpha 0.4）<br>② 中央大字"被处决"<br>③ 抖动 4f | 1.5 s | 明确的"我做错了什么"信号 |
| **处决成功（自身）** | ① 中央横幅"处决"（金色，带装饰线）<br>② 条带扫光 | 2.0 s | 高光时刻 |
| **击杀敌方** | ① 敌方名牌碎裂动效<br>② 中央提示"击破 XXX"（中号） | 1.8 s | |
| **队友被击杀** | ① 屏幕边缘蓝边脉冲 3 次<br>② 队友头像置灰 + 碎裂 | 2.0 s | 团战信息，必须显著 |
| **队友处决成功** | ① 队友头像高亮 2 s<br>② 屏幕角落小字 | 2.0 s | 弱于自身事件，不抢主视角 |
| **最后一击杀（回合结束）** | ① 慢镜 0.5 s（×0.20）<br>② 全场去饱和 + 胜方染色<br>③ 大字"胜 / 败" | 3.0 s | |

**团战 UI 的层级原则（3v3 核心）：**

```
P0  自身受击 / 被处决      ← 必须占屏幕中央
P1  自身处决 / 击杀        ← 中央横幅
P2  自身韧性归零（破防）   ← 中央提示
P3  队友被击杀            ← 屏幕边缘 + 头像
P4  队友击杀 / 处决       ← 屏幕角落
P5  敌方状态变化          ← 名牌 / 头顶条
```

**3v3 的 UI 信息量远大于 1v1，因此必须"分级降噪"：** 非 P0/P1 的事件**不得占用屏幕中央区域**，只能出现在屏幕边缘或世界空间 UI 上。否则团战时屏幕中央会被横幅糊满。

### 11.2 波形结构定义

```
轻击 (40 ms)：
  强度
  0.30 ┤  ▄▄
       │ ████
       │▀▀▀▀▀▀▀▀▀
  0.00 ┼────────────
       0ms      40ms
  特征：attack=0ms，decay=40ms（线性）
  感知："嗒"

重击 (90 ms)：
  强度
  0.70 ┤ ▄▄▄        ▄▄
       │████▄      ████▄
       │▀▀▀▀▀▀▄▄▄▄▀▀▀▀▀▀▀
  0.00 ┼────────────────────
       0ms   30ms      90ms
  特征：两个峰（0ms 与 30ms），第二峰为第一峰的 60%
  感知："咚—咚"

弹反 (120 ms)：
  强度
  0.90 ┤▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄
       │████████████████████▄▄▄
       │▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
  0.00 ┼──────────────────────────
       0ms       80ms         120ms
  特征：方波保持 80ms（!!），然后快速衰减 40ms
  感知："嗡——"（持续感，不是"咔"）
  设计意图：方波 = 时间被"按住"不动，呼应 12f 的最长顿帧
```

**弹反的方波是全文档最重要的触觉设计。** 其他所有事件都是"撞击型"波形（快起快落），只有弹反是**"按住型"波形**。这给了玩家一个物理上完全独立的感知通道——**闭着眼睛摸手柄，也能知道刚才那一下是弹反。** 这就直接服务于 §13 的盲测标准。

### 11.3 触觉叠加规则

```
规则 1｜不重叠原则
  新的触觉事件到来时，若前一次仍在播放：
    若新事件强度 ≥ 前一次 × 0.8 → 立即中断旧的，播放新的
    否则 → 队列等待，最多排队 2 个，超出的丢弃

规则 2｜强度封顶
  单次触觉强度 ≤ 0.95（不允许 1.0，留出余量防止马达饱和失真）

规则 3｜团战降级
  同屏 ≥ 6 角色时：
    非自身受击的触觉全部取消（队友/敌人的震动不传递给玩家）
    仅保留自身事件 + 处决 + 弹反

规则 4｜可访问性
  必须支持 3 档：关闭 / 弱（×0.5）/ 标准（×1.0）
  关闭触觉不得影响任何其他通道
```

**规则 3 的理由：** 触觉是**贴身通道**。让玩家为队友的受击产生震动，会严重混淆"我在挨打"和"队友在挨打"这两个必须区分的状态。**触觉只服务于玩家自身的身体感。** 这也是触觉通道与视听通道的根本区别——视听是**全场信息**，触觉是**本体感受**。

### 12.2 降级优先级（从先砍到后砍）

**这是本节最重要的表。砍错顺序会毁掉手感。**

| 顺序 | 降级项 | 削减量 | 性能收益 | 手感损失 | 决策 |
|---|---|---|---|---|---|
| **1** | **残影** | 100% 关闭 | 中 | **极低** | ✅ 第一个砍 |
| **2** | **L4 环境混响** | −6 dB / 关闭 | 低 | **低** | ✅ |
| **3** | **粒子数量** | −50% | **高** | 中 | ✅ |
| **4** | **拖尾** | −50% 长度 / 关闭 | 中 | 中 | ✅ |
| **5** | **屏幕震动振幅** | ×0.5 | 低 | 中 | ⚠️ |
| **6** | **摄像机推拉 / FOV** | 全部关闭 | 低 | 中高 | ⚠️ |
| **7** | **材质受击的次级参数** | 只保留 BaseColor | 低 | 低 | ✅ |
| **8** | **慢镜** | 时长 ×0.5 | 低 | 中高 | ⚠️ |
| **9** | **顿帧** | **绝不削减** | **0（几乎免费）** | **极高** | ❌ **禁止** |
| **10** | **L2 撞击音** | **绝不削减** | 0 | **极高** | ❌ **禁止** |
| **11** | **命中特效的生成帧** | **绝不延后** | 0 | **极高** | ❌ **禁止** |

**三条不可降级线（这是本文档的底线）：**

```
❌ 顿帧不可降级
   理由：顿帧的计算成本几乎为 0（只是停止一个计时器），
        但它是打击感的核心。没有任何性能理由能证明削减它是合理的。

❌ L2 撞击音不可降级
   理由：它是白皮书 §7 验收标准（"闭眼听出打没打中"）的唯一承载者。
        L1/L3/L4 都可以砍，L2 一个采样都不能少。

❌ 命中特效的生成帧不可延后
   理由：延后 1 帧就违反了 §3.1 零延迟原则。
        如果性能不够，应该减粒子数（顺序 3），而不是延后生成帧。
```

### 12.3 3v3 团战自动降级

**触发条件（满足任一即进入团战模式）：**

```
· 同屏角色 ≥ 6 个
· 300 px 半径内 ≥ 3 个角色处于交战状态
· 上一秒内命中事件 ≥ 5 次
· 帧率连续 30 帧 < 55 FPS（动态检测）
```

**团战模式降级清单：**

| 项目 | 常态 | 团战模式 | 依据 |
|---|---|---|---|
| 残影 | 按事件 | **全部关闭** | §12.2 顺序 1 |
| L4 混响 | 按事件 | **−6 dB 常驻** | §7.4 |
| 粒子数 | 100% | **×0.6** | §12.2 顺序 3 |
| 拖尾长度 | 100% | **×0.5** | §12.2 顺序 4 |
| 非自身触发的事件特效 | 完整 | **粒子 ×0.4** | 保留自身事件完整 |
| 摄像机推拉 | 启用 | **锁定 480 px** | §6.4 规则 4 |
| FOV 变化 | 100% | **×0.5** | §6.4 规则 4 |
| 非自身事件的屏幕震动 | 按叠加规则 | **振幅 ×0.5** | §5.3 优先级 |
| 非自身事件的触觉 | 无 | 无 | §11.3 规则 3 |
| **顿帧** | 按 §4.1 | **不变** | 不可降级线 |
| **L2 撞击音** | 完整 | **完整** | 不可降级线 |
| **命中特效生成帧** | `H` | **`H`** | 不可降级线 |

**团战模式退出条件：** 上述触发条件全部不满足，且持续 **3 秒（180 帧）** 后退出（防止边界抖动导致反复切换）。

### 12.4 动态帧率保护

```
监控：最近 120 帧（2 秒）的平均帧时间
分级：
  平均 ≤ 18.0 ms（≥ 55 FPS）  → L0 正常
  平均 ≤ 20.0 ms（≥ 50 FPS）  → L1：应用 §12.2 顺序 1~3
  平均 ≤ 24.0 ms（≥ 41 FPS）  → L2：应用顺序 1~6 + 团战模式
  平均 > 24.0 ms（< 41 FPS）  → L3：应用顺序 1~8 + 团战模式 + 粒子 ×0.4

恢复：需要连续 3 秒优于当前档位的阈值才降档恢复（迟滞，防抖动）
```

**注意：帧率保护绝不改变逻辑帧。** 逻辑仍然跑在固定的 1/60 秒步长上。降级只削减**表现层**（粒子、残影、混响）。如果逻辑帧也变了，白皮书 §3.3 的全部帧数据推导当场失效——**这是一个战斗系统能不能上线的红线。**

### 13.2 主观盲测方案（核心验收手段）

**这是本文档区别于"参数表"的地方——参数对了不代表手感对了。**

#### 测试 1｜静音画面测试（视觉单通道）

| 项目 | 内容 |
|---|---|
| **目的** | 验证视觉反馈是否足以区分事件类型（不依赖音效） |
| **方法** | 关闭全部音频，仅播放画面。测试者观看 60 次随机命中录像（轻击 / 重击 / 弹反 / 格挡各 15 次），判断类型 |
| **样本** | ≥ 12 名测试者，其中 ≥ 4 名无该游戏经验 |
| **通过标准** | 平均正确率 **≥ 80%**；新手组 ≥ 70% |
| **失败处理** | 检查 §8.2 特效生命周期差异、§9.2 位移差异、§5.1 震动差异是否足够大 |

#### 测试 2｜盲听测试（音频单通道）★ 最关键

白皮书 §7 验收标准原文：**"我能闭眼听出打没打中。"**

| 项目 | 内容 |
|---|---|
| **目的** | 验证音效是否构成独立且完整的确认通道 |
| **方法** | 关闭画面与手柄触觉，仅播放音频。测试者听 80 次随机事件（命中 40 / 空挥 20 / 格挡 10 / 弹反 10），判断"打中了 / 空了 / 被格挡 / 弹反" |
| **样本** | ≥ 12 名测试者 |
| **通过标准** | ① **命中 vs 空挥** 正确率 **≥ 95%**<br>② **四分类** 正确率 **≥ 85%**<br>③ 格挡 vs 命中 混淆率 **≤ 10%** |
| **失败处理** | 检查 §7.1 的 L2 四分支是否全部实现、§7.3 格挡低通滤波是否生效、L1 风声是否被过度放大 |

> **空挥识别率是 95% 这个高标准，是因为空挥必须"安静且空"。** 如果玩家听不出自己空挥了，白皮书 §8.3 的"空挥杀势 −4"惩罚就是不可学习的——玩家会莫名其妙掉杀势。

#### 测试 3｜触觉盲测（触觉单通道）

| 项目 | 内容 |
|---|---|
| **目的** | 验证触觉是否能独立区分轻 / 重 / 弹反（白皮书 §7："我手上有感觉"） |
| **方法** | 关闭画面与音频，仅握持手柄。测试者感受 60 次事件（轻击 20 / 重击 20 / 弹反 20），三分类 |
| **样本** | ≥ 12 名测试者 |
| **通过标准** | **三分类正确率 ≥ 85%** |
| **失败处理** | 检查 §11.2 波形结构——**弹反必须是方波**，这是三分类的关键区分点 |

#### 测试 4｜帧步进目视测试（工程验收）

| 项目 | 内容 |
|---|---|
| **目的** | 逐帧验证 §3.3 的六张时刻表 |
| **方法** | 游戏内帧步进工具（逐帧推进）+ 录制。对六类事件（轻击命中 / 重击命中 / 格挡 / 弹反 / 破防 / 处决）各录一次，逐帧截图，与时刻表逐行比对 |
| **样本** | 主策 + 程序 + 音频各 1 人独立比对 |
| **通过标准** | 三方比对结果一致，且与时刻表**零偏差** |
| **失败处理** | 差异 ≥ 1 帧即视为不合格，必须修复 |

#### 测试 5｜手感主观评分

| 项目 | 内容 |
|---|---|
| **目的** | 捕捉量化指标无法覆盖的"微妙不适" |
| **方法** | 5 分制问卷（1=很差，5=很好），含 5 个维度：重量感 / 清晰度 / 响应性 / 爽快度 / 疲劳感（反向计分） |
| **样本** | ≥ 20 名测试者，其中 ≥ 8 名无经验 |
| **通过标准** | 各维度均分 **≥ 4.0 / 5.0**，且最低单项 ≥ 3.5 |
| **失败处理** | 分析低分维度的关联参数，走 §1.3 变更流程 |

## 附录 B：术语与缩写
