## 一、我对这个岗位的理解

JD 的三条职责，我理解不是三件事，而是**同一条链路的三个环节**：

```
① 设计战斗机制  →  定义「规则」：什么相克什么，几帧起手，几帧收招
② 扩展战斗玩法  →  让规则长出「选择」：玩家在同一时刻有多个可选动作，且各有代价
③ 提升战斗表现  →  把规则的「结果」翻译成玩家能感知的信号：顿帧、震屏、音效、镜头
```

**第 ① 步决定游戏能不能玩，第 ② 步决定游戏能玩多久，第 ③ 步决定玩家愿不愿意承认自己被打中了。**

这三条里，我认为最容易被低估的是第 ③ 条。很多项目把"打击感"当成美术或程序的事，但**打击感的本质是一组参数**——顿帧几帧、震动多少毫秒、特效在哪一帧生成。这些参数**只有战斗策划能定**，因为只有战斗策划知道判定帧在第几帧、这一下有几分利。

我在作品 ⑥《打击感与表现规范》里把这件事做成了可执行的工程规范：每一次命中都有一张**精确到帧的四通道时刻表**（视觉 / 音频 / 摄像机 / 触觉），并写死了一条铁律——

> **所有反馈必须在判定帧当帧触发。** 超过 3 帧（50ms），玩家就会隐约觉得"打到了但没反应"。

累计 **10000+ 小时**。我做作品 ⑤ 时，拆解王者荣耀的对抗结构写了 15,000 字，**没有查任何资料**——这些是我打了 8 年、反复观测和琢磨过的东西。

### 2. 我能把"体感"翻译成"参数"——这是我最核心的差异化

玩家说："这一刀砍下去**软绵绵的**。"
我能翻译成：*"顿帧少了 3 帧、震动振幅低于 8px、音效缺低频层、命中特效生成延迟了 2 帧。"*

玩家说："这两个英雄**打起来太憋屈**。"
我能翻译成：*"A 的起手比 B 快 4 帧，导致 A 赢下每一次同帧交换；而 B 的补偿（伤害 ×1.18）不足以覆盖 4 帧的速度差。"*

**这个"翻译能力"，就是战斗策划的核心生产力。** 我在作品集里把每一次翻译都做了出来：白皮书 §3.3 用「有利帧 = 受击僵直 −（总帧 − 起手）」把"谁压谁"算成了确定的数字；技能集 §1 用「抢帧顺序」把"谁快谁慢"变成了可验证的排序。

### 3. 金融科班的建模能力 + Python，让我能自己验证自己的设计

这一点是我和其他战斗策划候选人最大的不同。

**大多数策划写完数值方案，只能等程序和测试来告诉他平不平衡。我可以自己先跑一遍。**

- 我独立开发过 RAG 知识库系统，并**自建引用率 / 检索命中率 / 幻觉率三指标评估体系**，主导 Bad Case 归因与参数调优——这套"定义指标 → 埋点取数 → 归因 → 调优"的方法，和调战斗数值是同一件事；
- 金融科班训练了统计与计量基础，我习惯**先建立模型再下结论**，而不是凭感觉；
- 因此我在这份作品集里写了 `combat_balance_sim.py`——一个**帧级蒙特卡洛仿真**，用与可玩原型完全相同的规则（含 8 个武学技能），**累计跑过 20 万局**，验证 5 项平衡命题。

**结果它推翻了我自己的一个设计假设**（详见仿真报告 §5）：我设计了 3 帧起手的快攻职业「影梭」，并自信地用 28% 的伤害惩罚去平衡它的速度优势。仿真跑出来 **93.7% 胜率**——完全失控。

原因很讽刺：**3 帧 = 50ms，在物理上不可能被反应**（人类简单视觉反应时约 200ms）。所以它不是"快"，而是"无法防御"。而我自己的白皮书 §2.2 里，白纸黑字写着：

> **"相克关系必须是可被观察的，否则博弈退化为运气。"**

**我违反了自己定的原则，是数据把我抓出来的。** 修正为 5 帧起手后，影梭回落到 43.8%（后续迭代到 49.1%）。

> 这件事我特别愿意在面试里展开——**因为它证明我不是在"做文档"，而是在"做设计"**。设计的本质就是提出假设、验证假设、然后承认自己错了。

### 4. 我能把手感做成能玩的东西，而不只是能读的东西

我具备完整的动手能力（Python / TypeScript / JavaScript / Git / Docker），并且**用 AI 工具显著放大了产出效率**。

所以这份作品集里的原型，是一个**单文件 HTML、零依赖、双击即玩、60FPS 帧精确**的战斗原型：

- 4 个职业，24 个招式，全部按文档的帧数据实现；
- 右侧面板**实时显示当前招式的起手/判定/收招/有利帧**，面试官可以一边打一边对照文档核验；
- 内置交锋日志，记录每一次命中与被格挡的有利帧；
- 我写了两个脚本自动核验：**原型端 216 项 + 仿真端 240 项，全部一致**（4 职业 × 6 招式 × 6 字段 + 有利帧 + 8 个技能）。

**我认为一个战斗策划如果只能交文档，他的设计就永远停在纸面上。** 原型能让分歧在 30 秒内被解决——"你说的手感不对"，打开打一局就知道。

### 5. 踏实负责：我留下了自己失败的过程，也交出了最终达标的结果

仿真报告里我完整保留了 **12 轮调参记录**，包括每一次的胜率变化、每一轮为什么这么做、两处失败的调参、以及最后为什么收手：

| 轮次 | 关键动作 | 结果 |
|---|---|---|
| 1~2 | 修正 AI 靠近方向反了；补"惩罚收招"的必要条件 | 矩阵不再退化 |
| 3 | **修正霸体从未参与判定的 bug** | 重锋 16.8% → 38.9% |
| 4 | **修正命中结算顺序偏差** | 矩阵恢复对称（此前 A/B 视角胜率之和达 111.6%） |
| 5 | 影梭起手 3f → 5f（呼应"可观察性"原则） | 影梭 93.7% → 43.8% |
| 6 | 参数压缩实验 | ⚠️ **失败**，极差反而从 10.1pp 恶化到 23.2pp → **回滚** |
| 7 | **实装 8 个武学技能**（原型 + 仿真） | 矩阵达标数 6/12 → 9/12 |
| 8~9 | 打击欲随技术下降 + 退避重整行为 | 9/12 → 11/12；TTK 三档拉开梯度 |
| 10~12 | 长策改走"强化枪阵"而非加伤害；困兽之斗改为连续型补偿 | **12/12**，极差收敛到 1.2pp |

**这一轮迭代最关键的一次认知修正，恰好推翻了我自己上一版的诊断**：

上一版我以为矩阵硬克制是"**速度 × 距离的量纲问题**"，准备了三条数值修正路径。但真正跑通之后才发现——**根因不是数值，是行为模型**：

> 初版的 AI **只会进攻、不会管理风险**。它永远在换血，于是"帧数快"和"距离长"这两个优势被无限放大。加上"韧性低于阈值就退避重整"这一条行为之后，快攻角色打不动乌龟、远距离角色守不住贴身，硬角自己就消失了。
>
> **结论：矩阵跑出硬克制时，先检查模型里的玩家会不会"不打"——很多时候问题不在数值，在于你的 AI 比真人更莽。**

**最终结果（每格 1,500 局）：**

| 指标 | 目标 | 实测 |
|---|---|---|
| 四职业平均胜率 | 48%~52% | **48.6% / 49.8% / 49.1% / 49.6%**（极差 1.2pp） ✅ |
| 反制矩阵 | 42%~58% | **12/12 全部落入**（44.3%~56.1%） ✅ |
| 中水平 TTK | 16~22 秒 | **19.3 秒** ✅ |

**唯一没达到的是「落后 60 杀势时胜率 35%~42%」——实测 43.7%，超出上沿 1.7 个百分点。** 我没有把它藏起来，也没有为了达标去削弱那个机制；我做的是**把评估口径从"单点阈值"改成"曲线单调性 + 每档梯度 + 全区间幅度"**，并把完整曲线附上：

> 均势 52.6% → 压制（−30）48.2% → 掌控（−60）44.2% → 碾压（−90）40.2%，**每档约值 4 个百分点，全区间 −12.4pp**。

**一条单调、等距、有完整梯度的价值曲线，比某个单点刚好落在区间内更有设计价值。** 原始指标的未达标我保留在报告里，没有删改。

## 三、我为什么想来雷火做战斗

雷火有《永劫无间》这样把**冷兵器博弈**做到世界级的产品，也有《逆水寒》这样长线运营的重度 MMO——这意味着雷火的战斗策划要同时面对两个极端：

- **竞技向**：帧级精度、读心博弈、职业平衡，任何 1 帧的偏差都会被顶级玩家放大；
- **长线向**：数值要能撑住几年的版本迭代，不能一次调崩。

**我的作品集恰好同时练了这两件事**：《止戈》的帧数据与博弈结构是竞技向的；而仿真里那 12 轮调参、以及"哪些旋钮该先动、哪些不能动"的判断（白皮书 §5.3），是长线向的。

我也很清楚自己的短板：**我没有真实的项目经验，我的设计没有经过真人玩家的检验。** 仿真里的"玩家"是我写的 AI 策略，它只能近似，不能替代真人。

但我相信两件事：

1. **我可以很快补上这一课**——从 10000+ 小时的玩家体感出发，加上建模与动手能力，我能把"玩家在骂什么"翻译成"哪个参数该动"；
2. **在这个岗位上，我愿意从最小的事情做起**：拉一次帧数据表、做一次手感联调、跑一次平衡数据、改一个让玩家骂了很久的手感细节。
